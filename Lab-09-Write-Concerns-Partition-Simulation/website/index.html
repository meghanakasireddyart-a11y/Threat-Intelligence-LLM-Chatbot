Key Theoretical Takeaways:

  • w:1 (Fastest, ~1000 ops/s): Returns immediately once written to Primary's in-memory WiredTiger cache. Vulnerable to failover rollbacks.
  • w:majority (~270 ops/s): Requires oplog network replication to at least 1 secondary. Guarantees zero data loss across failovers.
  • w:all (~145 ops/s): Waits for all secondaries; bound to the slowest network link or lagging node in the topology.

Question Answered: Does journaling add significant latency?

YES. For local writes (w:1), journaling increases latency by over 238% (+2.33 ms per write), reducing throughput by ~70%. This is because physical disk head / flash cell synchronization (fsync) is orders of magnitude slower than DRAM access. For w:majority and w:all, network round-trip time (RTT) already forms a large baseline, but journaling still adds an unavoidable ~2.1-2.6 ms storage penalty.

Activity 9.2: Minority Partition & Automatic Primary Stepdown

Anti-Split-Brain Protection

When BOTH secondaries are disconnected, the Primary is left alone in a minority partition (1/3 nodes). Attempting a w:majority insert will time out, and after electionTimeoutMillis (10s), the Primary automatically steps down to SECONDARY to prevent split-brain writes.

Timeline of State Transitions

T+00s Normal state: mongo-rs0-1 is PRIMARY (Term 1). Quorum 3/3.
T+05s Network partition disconnects rs0-2 and rs0-3. Primary left alone (1/3).
T+06s Attempt w:majority write: Times out after 5,000ms with WriteConcernError.
T+15s Primary Steps Down: mongo-rs0-1 detects no majority heartbeats and steps down to SECONDARY. Cluster is READ-ONLY.
T+35s Network reconnected. Election called: Term increments 1 -> 2. mongo-rs0-2 elected new PRIMARY.
